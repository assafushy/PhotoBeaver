# Decisions

Decisions made where `SPEC.md` is silent or where implementation details needed a choice. Newest milestone first.

## M2 - Plugin system (2026-10-03)

| #   | Topic                             | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                              | Why                                                                                                        | Status              |
| --- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------- |
| D52 | Plugin build tool                 | `pb-plugin build` bundles plugins with esbuild into one ESM file, `dist/index.js`. The scaffold has no tsup (SPEC 5.5 names tsup).                                                                                                                                                                                                                                                                                                                    | One tool for dev, pack and CI; a scaffolded project needs only the SDK and the CLI.                        | Approved in M2 plan |
| D53 | Plugin Inspector                  | Deferred to M6 (live RPC trace, job history, per-host CPU and memory). The Plugins screen shows status, restarts and logs.                                                                                                                                                                                                                                                                                                                            | Not in the M2 bullet list.                                                                                 | Approved in M2 plan |
| D54 | Uninstall, keep data              | When the plugin still has sources, its `plugins` row stays with `install_path = NULL` and the screen shows "Uninstalled, data kept". "Remove data" deletes its sources first.                                                                                                                                                                                                                                                                         | `sources.plugin_id` references `plugins`.                                                                  | Approved in M2 plan |
| D55 | Watch batches                     | Written with the batch writer but without moving `sync_cursor`. They use the source's in-progress run id when a sync is running, so a concurrent full scan does not tombstone files the watcher just added.                                                                                                                                                                                                                                           | Watch and resumable full scans must not interfere.                                                         | Approved in M2 plan |
| D56 | SDK distribution                  | Not published to npm yet. `create-photobeaver-plugin --sdk <path>` links a local SDK; scaffolds also depend on `@types/node` because the SDK ships TypeScript sources.                                                                                                                                                                                                                                                                                | Publishing comes with the registry (M6).                                                                   | Approved in M2 plan |
| D57 | RPC details                       | Streams use one-item credit (the producer pulls the next item only after an ack). Byte streams go as chunks of at most 1 MB, copied rather than transferred because MessagePortMain only transfers ports. Timeouts: host init and `testSource` 1 minute, `setupSource` 10 minutes, sync 10 minutes without a batch, byte streams 5 minutes without a chunk. `getThumbnail` streams a `{ found }` marker first.                                        | SPEC 6.5 backpressure, hang detection.                                                                     | Accepted            |
| D58 | Host crash and job retry          | A dead host surfaces as `HostCrashedError` carrying the restart delay. The job fails as an attempt and is requeued after that delay; `JobQueue.fail` honors an error's `retryAfterMs`. The handle drops its connection as soon as the RPC port closes, before the process exit event arrives.                                                                                                                                                         | SPEC 7.6, without waiting for the generic 30 second retry.                                                 | Accepted            |
| D59 | Permission guards                 | Installed before the plugin module loads. Folders are granted under both their given and real paths (macOS `/var` is a symlink). Guarded `fs.promises` functions reject instead of throwing. Native code can bypass the guards, as SPEC 6.6 states.                                                                                                                                                                                                   | Plugins' top-level code is covered too.                                                                    | Accepted            |
| D60 | Filesystem grants                 | A host may touch its data folder, its temp folder, its own install folder, every `format: "directory"` value of its sources' configs and every folder picked through `ctx.ui.pickDirectory`. Grants are per host, not per call.                                                                                                                                                                                                                       | One host serves all of a plugin's sources.                                                                 | Accepted            |
| D61 | Default plugins                   | The build copies them to `out/main/default-plugins/`, and packaged apps ship them outside the asar as `resources/plugins` (SPEC 5.4), because files cannot be copied out of an asar folder. At startup each is installed into `<userData>/plugins/<id>/<version>/` if missing, or upgraded when the bundled version is newer. Defaults the user uninstalled are remembered in `settings` (`plugins.removedDefaults`) until "Restore default plugins". | SPEC 9.1 with no consent dialog, and uninstall sticks.                                                     | Accepted            |
| D62 | Developer socket                  | A per-user Unix socket in the temp folder, or a named pipe on Windows (`PB_DEV_SOCKET` overrides it). It listens only while developer mode is on and accepts `load` and `reload` lines. Hot reload is driven by `pb-plugin dev`; the app does not watch `dist/` itself.                                                                                                                                                                               | One reload path; only the signed-in OS user can reach the socket.                                          | Accepted            |
| D63 | Local folder sources              | New local sources default to watch mode with a daily safety full scan. The scheduler's due query includes watch-mode sources for that scan.                                                                                                                                                                                                                                                                                                           | SPEC 9.2.                                                                                                  | Accepted            |
| D64 | Host process                      | `utilityProcess` per plugin with only PATH, temp and locale variables in its environment, `--max-old-space-size` 1024 MB (4096 MB for GPU or CPU-heavy plugins), and stdout and stderr appended to `logs/plugin-<id>.log`. The host is a second main-build entry; build chunks stay in `out/main` so relative paths resolve.                                                                                                                          | SPEC 6.6 resource limits; no secrets in the host environment.                                              | Accepted            |
| D65 | Reinstalling the same version     | Replaces the version folder in place, so a failed reinstall of the same version cannot roll back to the old files. Different versions roll back fully.                                                                                                                                                                                                                                                                                                | Rare in practice; avoids keeping two copies of every install.                                              | Accepted            |
| D66 | `ctx.settings()`                  | Returns `{}` until enricher settings exist (M3). Secrets and OAuth still throw "not available" (M4).                                                                                                                                                                                                                                                                                                                                                  | Scope.                                                                                                     | Accepted            |
| D67 | Testing the host                  | Unit tests run the real host runtime in-process over memory ports, with process-wide guards turned off and the plugin module injected. Guards are tested in an isolated worker. The real `utilityProcess` path is covered by e2e tests (host kill, scaffold to install).                                                                                                                                                                              | The plan's worker-thread test could not load TypeScript workspace sources; this keeps coverage without it. | Accepted            |
| D68 | Source and plugin state in the UI | Sources show when their connector is missing or disabled. Plugins show Enabled, Disabled, Crashed, Cannot load (with the error) or "Uninstalled, data kept".                                                                                                                                                                                                                                                                                          | SPEC 7.6 notification with "View logs" and "Re-enable".                                                    | Accepted            |

## M1 - Core pipeline and local connector (2026-10-03)

| #   | Topic                               | Decision                                                                                                                                                                                                                                                                 | Why                                                                                                                                                              | Status                   |
| --- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| D23 | Thumbnail workers                   | No `worker_threads` pool in M1 (SPEC 3.1 asks for one). The core lane runs up to `cores - 1` thumbnail jobs; sharp decodes and resizes on libvips' own thread pool.                                                                                                      | sharp already keeps the JS thread free, and sharp inside worker threads has known native-crash pitfalls. Revisit if profiling shows main-thread stalls.          | Approved in M1 plan      |
| D24 | `connector-local` watch mode        | Deferred to M2. M1 polls hourly (`defaultIntervalSec` 3600) plus "Sync now".                                                                                                                                                                                             | The spec ties `watch()` to the plugin host lifecycle, which arrives in M2.                                                                                       | Approved in M1 plan      |
| D25 | Grid data loading                   | The renderer loads every asset summary in keyset pages of 1000, then lays out and virtualizes on the client.                                                                                                                                                             | Keeps the timeline scrubber exact without estimated section heights. About 12 MB at 200k assets, streamed after the first page renders.                          | Approved in M1 plan      |
| D26 | Original cache                      | The viewer and video thumbnails read originals through `cache/originals/` (LRU by mtime, 5 GB default), including local files. Image thumbnails stream straight into sharp.                                                                                              | One code path for every connector, behind an interface a future archive store can sit beside (SPEC 13 #2).                                                       | Approved in M1 plan      |
| D27 | Missing assets                      | New column `assets.missing_since`: set when the last live instance is tombstoned, cleared when one reappears. The grid hides missing assets; maintenance purges them after 30 days with their files.                                                                     | SPEC 4.3 "Missing" needs a cheap, indexable flag.                                                                                                                | Accepted                 |
| D28 | D14 resolution                      | Partial expression index `assets_library_order_idx` on `(COALESCE(captured_at, -9007199254740991), id) WHERE hidden = 0 AND missing_since IS NULL`. Undated assets use `Number.MIN_SAFE_INTEGER`. A unit test checks the query plan uses the index without a temp sort.  | Grid pages come from an index scan, and pre-1970 photos sort above undated ones.                                                                                 | Accepted                 |
| D29 | D10 resolution                      | `plugin_kv.value_json` is NOT NULL. `storage.set(key, undefined)` and `storage.delete(key)` remove the row.                                                                                                                                                              | A stored null and a missing key can no longer differ.                                                                                                            | Accepted                 |
| D30 | D17 resolution                      | `PB_USER_DATA_DIR`, and the new `PB_SYNC_BATCH_DELAY_MS` (a pause between sync batches, used by the crash e2e test), only apply when `!app.isPackaged`.                                                                                                                  | Test hooks never change a shipped app.                                                                                                                           | Accepted                 |
| D31 | Sync run id                         | `sources.sync_run_id` holds the id of the run in progress; it is cleared when a run completes. A resumed sync, whether from a retried job or a new one, keeps the same id.                                                                                               | Full-scan tombstoning compares `instances.seen_run_id` with the run id, so a resume must not start a new run.                                                    | Accepted                 |
| D32 | `ctx.isKnown`                       | Also marks the returned live instances as seen in the current run.                                                                                                                                                                                                       | Otherwise files a connector skips as unchanged would be tombstoned at the end of a full scan.                                                                    | Accepted                 |
| D33 | Job dedupe keys                     | A job releases its `dedupe_key` when it becomes `done` or `dead`.                                                                                                                                                                                                        | The key is UNIQUE and done rows live 24h, which would block the next scheduled sync of the same source.                                                          | Accepted                 |
| D34 | Lease recovery at startup           | Startup returns every leased job to the queue, not only expired ones.                                                                                                                                                                                                    | The single-instance lock rules out another worker, and waiting for leases to expire would delay resume by up to 2 minutes.                                       | Accepted                 |
| D35 | Sync failures                       | A failed sync still completes its job; the scheduler owns retry timing. The failure backoff `60s * 2^n` uses the failure count before this failure, so the first retry is after 60s.                                                                                     | Avoids two competing retry mechanisms.                                                                                                                           | Accepted                 |
| D36 | Merge snapshot and never-merge list | `asset_merges.snapshot_json` stores the merged asset, its memberships and what the merge added to the survivor. Unmerge restores them and reverts survivor fields the merge changed, unless the user edited them since. An undone merge row is the "never merge" record. | The spec's columns cannot restore a deleted asset; a separate blocklist table would duplicate data.                                                              | Accepted                 |
| D37 | Merge field rules                   | The survivor keeps its values; null fields are filled from the merged asset; capture time follows core-field precedence (survivor wins ties); favorite and hidden are kept if either asset had them.                                                                     | SPEC 4.3 plus SPEC 6.3 precedence.                                                                                                                               | Accepted                 |
| D38 | Thumbnail folders                   | `thumbs/<last 2 chars of id>/<id>_<size>.webp`.                                                                                                                                                                                                                          | Asset ids are ULIDs, whose first characters encode time, so the spec's "first 2 chars" would put nearly every file in one folder.                                | Accepted                 |
| D39 | Thumbnail size                      | `256` and `1024` are the shorter edge in pixels, images are never enlarged, WebP quality 80, EXIF orientation applied. Width and height on the asset are the upright dimensions.                                                                                         | Sharp tiles in a justified grid whatever the aspect ratio.                                                                                                       | Accepted                 |
| D40 | Undecodable formats                 | HEIC and most RAW files get `thumb_state = 'failed'` and a "No preview" tile.                                                                                                                                                                                            | The sharp prebuilt cannot decode them. Embedded previews come with the M3 metadata work.                                                                         | Accepted, see follow-ups |
| D41 | Time zones                          | `captured_at` is floating local time: the wall-clock reading encoded as UTC milliseconds. File mtimes are converted to the machine's wall clock on ingest. The UI formats every date in UTC.                                                                             | EXIF and filename dates carry no zone, and mixing them with absolute instants would shift days.                                                                  | Accepted                 |
| D42 | Dates from file names               | Recognized: `YYYYMMDD_HHMMSS` (optional milliseconds), `YYYY-MM-DD HH.MM.SS`, `YYYY-MM-DD`, `YYYYMMDD`, years 1900 to 2099, with calendar validation.                                                                                                                    | Covers common camera, phone and messaging app names.                                                                                                             | Accepted                 |
| D43 | Directory config                    | `configSchema` fields with `format: "directory"` render as a folder picker; `setupSource` validates the folder. Config is checked by a small validator in `packages/shared` (type, enum, minimum, maximum, required, defaults).                                          | The spec's example picks the folder inside `setupSource` but never returns it. A full JSON Schema engine can replace the validator if plugins need more.         | Accepted                 |
| D44 | In-process plugin context           | M1's `ctx` has working `log`, `storage`, `dataDir`, `signal`, `isKnown` and `reportProgress`. `secret` and `oauth` throw "not available until a later milestone", `fetch` is the global fetch without the allowlist, and `settings()` returns `{}`.                      | Those parts belong to M2 (host, permissions) and M4 (OAuth, secrets).                                                                                            | Accepted                 |
| D45 | `pb-media://` behavior              | A missing thumbnail answers 404 and raises its job to UI priority; the renderer reloads the tile on `thumbs.ready`. Originals support HTTP Range. The CSP keeps `connect-src 'self'`, so pages can show `pb-media:` images and video but cannot `fetch` them.            | Lazy, prioritized thumbnails; video seeking; less renderer surface.                                                                                              | Accepted                 |
| D46 | Push events                         | `library.changed` is throttled to once per second. `thumbs.ready` is batched every 250 ms and carries each asset's new size and thumbnail state, so tiles update in place.                                                                                               | A 10k-file sync must not trigger thousands of full refetches.                                                                                                    | Accepted                 |
| D47 | Removing a source                   | Deletes its instances and albums, then every asset left without instances, with thumbnails and cached originals. Adding and removing a source are written to `audit_log`.                                                                                                | SPEC 3.3 audit log; no orphan assets.                                                                                                                            | Accepted                 |
| D48 | Packaging native modules            | sharp's platform packages are `optionalDependencies` of the desktop app; sharp, `@img`, ffmpeg-static and better-sqlite3 are unpacked from the asar. The main entry imports the app code lazily.                                                                         | electron-builder does not follow sharp's optional packages in pnpm's layout, and an ESM main that fails while importing exits silently; now the error box shows. | Accepted                 |
| D49 | Lane behavior                       | Enqueue notifications are deferred to the next tick, so a lane never leases inside the caller's transaction. A job aborted on purpose (pause, remove) completes; jobs interrupted by shutdown keep their lease.                                                          | Correctness of transactional enqueue and clean cancel versus resume.                                                                                             | Accepted                 |
| D50 | Viewer                              | A nested route over the grid (`#/library/asset/:id`), so the grid keeps its scroll position. Arrow keys move from a position kept in a ref.                                                                                                                              | React Router renders navigations as transitions, so a quick second key press could act on the old position.                                                      | Accepted                 |
| D51 | Pause and Sync now                  | Pause aborts a running sync. "Sync now" on a paused source fails with "Resume the source before syncing it".                                                                                                                                                             | Pausing should take effect immediately and stay explicit.                                                                                                        | Accepted                 |

### Follow-ups from M1 (2026-10-03)

- **D40:** show embedded JPEG previews for HEIC and RAW once `enricher-metadata` (M3) can extract them.
- **D25:** if very large libraries load slowly on older machines, switch to estimated section heights without changing the IPC contract.

### Follow-ups from the M0 review (2026-10-03)

- **D14:** the grid orders by `COALESCE(captured_at, 0)` but the index is on plain `captured_at`, so SQLite cannot use it and sorts the whole table on every page. Add a matching expression index. Using `0` for undated assets also sorts pre-1970 photos below undated ones; use the minimum integer instead.
- **D10:** consider `NOT NULL` on `plugin_kv.value_json`, with deleting a key removing the row, so plugins never see a stored null that differs from a missing key. Cheapest before the first release, since SQLite needs a table rebuild to add the constraint later.
- **D17:** `PB_USER_DATA_DIR` is honored in packaged builds. Consider applying it only when `!app.isPackaged`.

All three were resolved in M1 (D28, D29, D30).
