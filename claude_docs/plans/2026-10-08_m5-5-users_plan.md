# M5.5 Users and roles - Implementation Plan

## Context

M5 is merged (`9d4d985`, CI green on all three OSes). SPEC 12 M5.5 delivers:
- **Accounts:** a multiple-users toggle, local accounts, a sign-in screen or user picker, auto-lock, a recovery key, and Touch ID on macOS.
- **Enforcement:** Viewer, Editor and Admin rules applied to every core request and to `pb-media://`, scopes applied in every library query, an audit log, and a Users screen.

**Acceptance:**
- A Viewer scoped to one album can't see, search or load anything outside it, even by guessing an asset id.
- An Editor can tag and merge, but can't add sources or plugins.
- The last Admin can't be removed.
- Sync keeps running while the app is locked.

Also in this milestone, as you asked: fix the Windows quit hang by redesigning quit (D133, D134).

**Spec references:** 3.3 (all of it), 4.2 (`users`, `user_scopes`, `audit_log`), 8.1 (Settings, Activity), 10 (security).

### Where the code stands
- **Permissions and session.** The 11 permission names and the role sets already exist (`packages/shared/src/permissions.ts`, `roles.ts`). The IPC registry checks `requires` against `session.permissions` (`ipc/registry.ts:74-88`). `SessionService` only supports an implicit admin (`main/session/session-service.ts`).
- **Tables.** `users`, `user_scopes` and `audit_log` match the spec. Nothing manages users yet.
- **Mis-assigned channels:**
  - `plugins.list` needs `plugins.manage`, but the nav uses it to decide whether People and Duplicates show, so those screens disappear for Viewers and Editors.
  - `plugins.rerun` (re-run on the whole library) needs only `sources.sync`.
- **Read paths with no scope** (each needs a scope): library query and totals, geo points, all facets, people list and faces, the duplicates list and recent merges, the asset detail and `openInSource`, the sources list, `pb-media` (thumbnails, originals and face crops), and the `thumbs.ready` event.
- **Editor features.** Favorite, user tags, hide, edit date or location, and user albums exist in the schema only. There is no IPC or UI for them.
- **Missing UI.** Activity and Settings are placeholders, and nothing in the renderer knows who is signed in.

## Decisions

Yours, from the questions:
1. **Editor features: core edits.** Favorite, user tags, hide, edit date and location, user albums (create, rename, delete, add and remove photos) and "Re-run enrichment" on a photo. Export and rotate get permissions only, and their features wait for M6.
2. **Touch ID is included.** It is an opt-in per user, on macOS, through `systemPreferences.promptTouchID`, and is covered by a manual check.
3. **The Windows hang is fixed by redesigning quit.** When the app quits, core aborts running jobs with a 1-second grace, kills every plugin host right away (no deactivate round trip), closes the database, then calls `app.exit(0)`, so it never relies on Electron's own quit sequence. The e2e `closeApp` fallback goes back to failing the test, so a hang can no longer pass silently.

Mine, to record:

4. **Password hashing.** argon2id through `hash-wasm`, which is WASM with no native module, using the OWASP parameters (m=19 MiB, t=2, p=1). Passwords are at least 8 characters, and PINs are 4 to 8 digits as in the spec. After 5 wrong attempts, each further try waits an extra 30 seconds, held in memory per user.
5. **Session states.**
   - Single-user mode, the default: the implicit Admin is always signed in, exactly as now.
   - Multi-user mode:
     - The app starts locked and shows the user picker. Signing in sets the current user, and Lock or Switch user clears it.
     - New channel flag `public: true` for the few channels that work while locked: `session.current`, `auth.users` (the picker list), `auth.signIn`, `auth.signInBiometric` and `auth.recover`. Every other channel, and `pb-media`, answers `LOCKED` while no one is signed in.
6. **Turning on multiple users.** The Admin sets a password, and the app shows a one-time recovery key (24 random characters, stored as an argon2id hash). Using the recovery key resets the password of the oldest Admin. Turning multi-user off needs the Admin's password and goes back to the implicit Admin. Accounts are kept, just unused.
7. **Auto-lock.** It is set in Settings (default 15 minutes, off in single-user mode). The main process checks system idle time (`powerMonitor.getSystemIdleTime`) every 30 seconds and also locks on the OS `lock-screen` event. The app menu gets "Lock" and "Switch user". Locking clears the renderer's query cache and shows the picker. Sync and enrichment keep running (SPEC 3.3).
8. **Scopes at the SQL level.**
   - The session holds an `AccessScope`: null for unscoped users and Admins, otherwise the user's source ids and album ids.
   - A single helper, `scopeCondition(scope)`, returns the SQL that decides visibility: an asset is visible if it has a live instance in a visible source, or is in a visible album (SPEC 3.3). It is added to `filterCondition` and to every raw read path listed above.
   - **Per path:**
     - The asset detail returns not-found when the asset is out of scope, and lists only instances in visible sources.
     - `openInSource` requires the instance's source to be visible.
     - Facets, people (faces of visible assets only), duplicate groups (shown only when every asset in them is visible) and recent merges are filtered the same way.
     - `pb-media` resolves the asset (for a face crop, through the face's asset) and checks scope before reading even a cached file.
     - `thumbs.ready` sends only the ids the signed-in user can see.
9. **Channel fixes.**
   - New `app.capabilities` (requires `assets.view`) answers "is a faces plugin enabled" and "is a merge plugin enabled" for the nav.
   - `plugins.rerun` moves to `plugins.manage`.
   - New `assets.rerun` (requires `sources.sync`) re-runs enrichment on chosen assets.
   - `sources.pause` and `sources.resume` stay at `sources.sync`.
10. **What the audit log records.** Everything already audited, plus:
    - people edits, album edits, and date, location and hide edits
    - settings changes
    - user creation, role and scope changes, disabling and deletion
    - turning multi-user on or off, and recovery key use
    - sign-in and sign-in failures (without the secret)

    A new `audit.list` (requires `library.admin`) is paged, and Activity shows it.
11. **The last Admin is protected.** Demoting, disabling or deleting the last enabled Admin is refused in core, inside the same transaction.
12. **Library lock file** (SPEC 3.3, two machines on one library). It stays deferred, as D18 already says, to the library-location work.

## Core (`apps/desktop/src/main`)
- **`session/`:**
  - `auth-service.ts`: hashing, verification, the delays after wrong attempts, the recovery key, and Touch ID through an injected `promptBiometric`, so core stays headless.
  - `session-service.ts`: current user or locked, sign-in, lock, switch, and a `scope()` for the current user.
  - `idle-lock.ts`: the idle check (Electron glue).
- **`core/users/user-service.ts`:**
  - Create, update (name, role, password or PIN, biometric, disabled), delete and set scopes, all with the last-Admin guard.
  - Turn multi-user on and off.
  - Reading and writing scopes.
- **`core/access/scope.ts`:**
  - `AccessScope`, `scopeCondition(scope)` and the visibility helpers `assetVisible(db, scope, id)` and `sourceVisible(db, scope, id)`.
  - Reused by: `library-filter.ts`, `facets.ts`, `people-queries.ts`, `duplicates-service.ts`, `asset-service.ts`, `asset-extras.ts`, `source-service.list`, `pb-media.ts` and the `thumbs.ready` event.
- **`core/assets/edit-service.ts`:**
  - `setFavorite`, `setHidden`, add and remove user tags, `setCapturedAt`, `setLocation`.
  - Date and location use precedence `user`, the existing top rank.
  - Search text is refreshed after each edit, and edits are audited.
- **`core/albums/album-service.ts`:**
  - User albums (`source_id` null): create, rename, delete, add and remove assets, and list them (scoped).
  - Source albums stay read-only.
  - The library filter gains `albumIds`.
- **IPC registry:**
  - Public channels skip the permission check but still validate input.
  - Locked sessions get the new error code `LOCKED`.
  - Handlers receive `ctx.scope`.
- **Quit redesign** (decision 3), in `main/index.ts`, `core.ts` and `host-handle.ts`. It adds `killAll()` with no deactivate step.

## UI (`apps/desktop/src/renderer/src`)
- **Auth gate.** `useSession()` wraps the app. When locked, it shows `SignInScreen`:
  - a user picker with avatars or initials
  - password or PIN entry, plus a Touch ID button when enabled
  - "Forgot password?" for the recovery key
- **Permission-aware UI.** `can(permission)` hides nav items and controls. Sources, Plugins, Activity and admin settings appear only for Admins. Duplicates and People actions appear only for Editors and Admins.
- **Viewer info panel** (Editor):
  - favorite star and Hide
  - a tag editor (add and remove user tags)
  - date and location editors
  - "Add to album"
  - "Re-run enrichment"
- **Albums screen.** It lists albums (user and source) and has create, rename and delete. Opening an album filters the library. The library grid's selection mode gets "Add to album" and "Remove from album".
- **Settings screen** (replaces the placeholder):
  - "Multiple users" toggle, with the flow that sets the Admin password and shows the recovery key once
  - auto-lock minutes
  - map tiles and "always ask", moved here from M3
- **Users screen** (`/settings/users`):
  - list, create and edit users (name, role, password or PIN, Touch ID, disabled)
  - a scope picker (sources and albums)
  - delete, guarded for the last Admin
- **Activity screen:** the paged audit log.
- **App menu:** "Lock" and "Switch user".

## Tests
- **Unit:**
  - **Auth:** hashing and verification, PINs, delays after wrong attempts, the recovery key, multi-user on and off.
  - **Users:** the last-Admin guard (demote, disable, delete), and role-to-permission mapping.
  - **Registry:** a locked session gets `LOCKED`, public channels pass, and every channel's `requires` is checked against SPEC 3.3's table, so a mis-assigned channel fails the test.
  - **Scope matrix, against a seeded library** with two sources, an album and faces:
    - an album-scoped Viewer sees only album assets in query, totals, search, facets, the map, people, duplicates, merges, the detail, `openInSource` and the sources list
    - pb-media for thumbnails, originals and faces: an out-of-scope id gives 404, the same as missing
  - **Edits and albums:** each edit, search text after tagging, user date precedence, album CRUD, and the `albumIds` filter.
- **Integration (headless core):** sign in as a scoped Viewer and run every read service. Sync and enrichment keep working while locked.
- **E2E, the acceptance:**
  - Turn on multiple users. The recovery key is shown. Create an Editor, and a Viewer scoped to the "Family" album.
  - **Viewer:**
    - sees only the album photos, and a search for a term from outside the album finds nothing
    - `pb-media` for a guessed out-of-scope id fails
    - has no Sources, Plugins or Duplicates actions
  - **Editor:**
    - tags a photo and the tag is searchable
    - merges a duplicate
    - Sources, Plugins and Users are missing, and calling `sources.add` directly is denied
  - **Admin:** demoting the last Admin is refused.
  - **Lock:** lock the app, add a file to the source while locked, unlock, and the file is there.
  - All existing e2e tests pass, still in single-user mode.
- **Windows hang:** the CI e2e run shows no `quit-hang` and `closeApp` fails on a hang again. The plugin, core and e2e suites all pass.
- **Manual (you):** Touch ID sign-in on a Mac.

## Risks
- **Scope leaks through a missed read path.** Mitigation: one shared `scopeCondition` helper, a matrix test that runs every read service as a scoped Viewer, and a registry test that lists every channel.
- **argon2 speed in WASM.** About 50 ms per hash at these parameters, which is acceptable for sign-in.
- **Quit redesign skips plugins' `deactivate`.** Plugin work is durable, and jobs re-run on the next start, so nothing is lost. The plugin guide will mention that `deactivate` is not called when the app quits.
